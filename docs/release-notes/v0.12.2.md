v0.12.2 修复 Android 上两个从真机日志里查到的问题：定点打卡被系统扣住，以及页面偶发「读取失败」。

## 修复

- **07:00 / 17:00 打卡不再被系统冻结扣住**：部分国产 ROM（实测 nubia MyOS 16）会在应用退到后台约 1 分钟后冻结进程，并把它的普通精确闹钟一起挂起，直到用户再次打开应用。权限、电池优化白名单、自启动全开也一样。现象是晚点不打，或者早点拖到下午才响、提示「被系统推迟到了窗口之外」。打卡与重试现在改用闹钟时钟（`setAlarmClock`），被冻结时也会准点唤醒应用。
  - 代价：状态栏会出现闹钟图标，锁屏或快捷设置里的「下一个闹钟」可能显示 07:00 / 17:00，点它会打开 TernDays。
  - 小组件的零点刷新仍是普通闹钟，被冻结时会推迟到下次打开应用或下次打卡时刷新。
- **「读取失败」不再误报**：数据刚变化时（例如打开应用时自动补打落库），被替换掉的那一轮读取被当成了失败，首页、城市详情、导出、设置页会闪出「读取失败」，个别情况下会一直停在失败卡片上，直到点「重试」。现在只有真的读库出错才会显示。

## 验证

- 真机（nubia NX888J，MyOS 16 / Android 16）：同一冻结状态下，普通精确闹钟被标记 `powerSaver restricted`，闹钟时钟不受限，并且准点（+32 ms）唤醒了被冻结的进程；装上 v0.12.2 后，应用被冻结时次日 07:00 的打卡闹钟仍为不受限。
- `:core` 测试全部通过。

可直接覆盖升级，无需卸载应用。
