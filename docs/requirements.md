# TernDays 需求说明（v0.2 · 已确认，进入开发)

一个统计「一个自然年内，你在每座城市各待了多少天」的移动应用。

- 平台：Android + iOS，**Android 优先开发**
- 页面原型：https://claude.ai/code/artifact/aea2442a-2347-410c-aeff-b2cd92225906
- 状态：2026-09-01 与产品负责人确认，原「待确认」项已全部拍板（见 §5）。

## 1. 核心机制：每日两次自动打卡

- 每天 **07:00** 与 **17:00**（手机当前本地时间）各自动记录一次位置（「早点」「晚点」）。
- 定位只用 **GPS / 系统定位服务**，不用 IP（境外 SIM / 代理场景 IP 不可靠）。
- 每次打卡存储：时间戳、时区、经纬度（仅本地保留）、解析出的城市。
- 需要「始终允许」后台定位权限；每天仅定位两次，无持续追踪。
- 系统约束：iOS / Android 均不保证后台任务整点执行，实际打卡落在目标时刻附近；应用做补偿：
  - 早点补捕窗口 07:00–11:59，晚点补捕窗口 17:00–23:59（闹钟延迟触发或打开应用时补打，标记「延迟」）；
  - 超过窗口未捕获记为「无记录」，可手动补记。
- **首点（v0.3）**：首次安装完成引导后**立即**记录一个点（任何时刻），给用户即时反馈；
  该点标记为 EXTRA，不占早/晚槽，只作所在半天的兜底样本（见 §2）。

### 1.1 Android 保活（国产 ROM 专项）

后台被杀是最大风险，设置页提供「打卡保障」引导，逐项检测与跳转：

1. 定位权限（前台 + 后台「始终允许」）
2. 精确闹钟权限（API 31+，`SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM`）
3. 通知权限（前台服务与补打提醒）
4. 电池优化豁免（`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`）
5. 厂商自启动 / 后台运行白名单：内置小米、华为/荣耀、OPPO/一加/真我、vivo/iQOO、三星、魅族等品牌的设置页跳转（逐个 try，失败则给文字指引）

### 1.2 时区与跨国（已确认策略）

- 打卡闹钟按**手机当前本地时间** 07:00 / 17:00；监听系统时区/时间变更广播后立即重排闹钟。
- 每条记录的「归属日期」= 捕获时刻在**当时时区**下的本地日期。
- 向西飞可能出现同一本地日期的同一时段两条记录：**保留最早一条**，其余忽略（不参与计天）；
  向东飞可能整段时间不出现 07:00：该时段缺record，按单点/无记录规则兜底。
- 该逻辑作为纯函数实现并配单元测试（两端共用同一套规则）。

## 2. 计天算法（已确认）

以自然年（1.1–12.31）为周期，每天最多 1 天。一天抽象为**上半天样本 + 下半天样本**
（早点=上半天样本，晚点=下半天样本）：

| 当天样本情况 | 计法 |
| --- | --- |
| 两个样本同城 | 该城市 +1 天 |
| 两个样本异城 | 两城市各 +0.5 天 |
| 只有一个样本 | 该城市 +1 天 |
| 全天无样本 | 计入「无记录」，可手动补记（补记整天算 1 天，标记「补记」） |

**首点（EXTRA）兜底规则**：正式早/晚点永远优先；仅当对应半天的正式点缺失时，
首点按捕获时刻顶替样本——<12:00 顶早点、≥12:00 顶晚点。因此：

- 凌晨装机（早于 7 点）：当天会打 3 个点，但早晚正式点优先，首点只兜底，仍然最多 1 天；
- 下午 4 点装机：当天 2 个点（首点+晚点）**同属下半天，不拆半天**，按单样本整天计；
  若晚点没打成，首点顶替晚点，当天照样计数；
- 凌晨装机在 A 城、早点缺失、晚上到 B 城：A +0.5、B +0.5。

## 3. 城市解析（离线，已确认粒度）

- **全程离线**：内置城市数据集 + 本地最近邻/边界匹配，坐标不发给任何服务（含系统地理编码服务）。
- 国内：**地级市 / 直辖市**粒度（如「杭州」「北京」）；境外：数据集中的城市名（中文名优先，无则原名）。
- 原始经纬度落库保留：后续版本升级解析算法后可对历史点**重新解析**。
- 已知限制（v0.1 如实标注）：市界边缘可能判给邻市。

### 3.1 边界准确度与交叉验证（v0.5，起因：人在深圳被判成香港）

- **数据集层**：深港/珠澳等真实边界两侧补密锚点（口岸/边界街区逐点标定），
  港澳救援判定按「距原生港澳点 vs 距内地锚点谁近」而非矩形框；32 个边界探针 + 12 个
  回归点全部通过后才允许发布。
- **打卡时交叉验证**（全离线、确定性）：取按城市去重的前 3 个候选，
  1. 前两名距离差 <「1.5km + 定位误差（封顶 3km）」判为**边界模糊区**；
  2. 模糊区内若 ≤36h 内上一次打卡的城市也在候选中，按**行程连续性**沿用它
     （真正跨城后深入新城市，边距拉大，连续性自动失效）；
  3. 定位误差 ≥1.5km（典型为基站定位漂移）时坐标本身不可信，误差圈内沿用上次城市；
  4. 防错误传播：最近候选距离 <0.8km 且定位可信时视为明确证据，不沿用。
- **数据集升级自动修复**：城市库带版本号，升级后用存量原始坐标把历史打卡重解析一遍
  （手动更正不受影响），并提示修正条数。

### 3.2 手动更正（v0.5，v0.7 增加半天粒度）

- **任何一天都可人工更正城市**（不再限于无记录日）：默认整天记入所选城市，
  优先级最高（覆盖自动打卡判定），标记「手动」，随时可**恢复自动判定**。
- **半天更正（v0.7）**：当天有早/晚两个样本时，可选择「只改上半天 / 只改下半天」，
  另一半天仍按打卡判定——跨城出行日只纠正错的那半天，保住正确的 0.5 + 0.5 拆分。
  整天更正与半天更正互斥（写入时自动清理另一种）。
- 入口：首页「今日打卡」的**纠正**按钮；城市详情月历/明细**点任意一天**；
  设置页保留无记录日补记与全部手动记录列表（可恢复自动）。

## 4. 页面（对应原型）

1. **权限引导**（首启）：机制说明 + 隐私承诺 + 权限逐项授予。
2. **首页**：年份切换；年初至今汇总（已记录天数 / 城市数 / 无记录天数）；今日早晚打卡状态；
   城市列表按天数降序——**大号城市名 + 大号天数的简洁列表（已按反馈去掉占比横条）**。
3. **城市详情**：全年累计；月历（全天 = 满色块，半天 = 斜半色块）；打卡明细（实际时间 + 城市）；
   点任意一天可更正城市（§3.2）。
4. **导出**：选年份；Excel(.xlsx) / CSV；内容 = 城市汇总 + 每日明细；本机生成走系统分享，不联网。
5. **设置**：打卡保障清单（§1.1）、手动补记与更正入口、数据说明。

## 6. 数据与隐私

- 所有数据仅存手机本地（Android: SQLite；iOS: 本地文件），无账号、无服务器、零联网。
- 删除应用即清除全部数据。

### 6.1 换手机数据迁移（v0.6，已确认方案：扫码配对 + 局域网直传）

- 用户确认不做云盘方案（Google Drive 依赖 GMS 对国内用户不可用；iCloud 不跨端），
  迁移**不经过任何服务器**，与零联网承诺一致（仅迁移页面临时使用局域网）。
- 流程：旧手机 设置 →「迁移到新手机」起一次性局域网服务并展示二维码
  （内容 = 本机局域网地址 + 随机端口 + 一次性 AES-256 密钥）；
  新手机 设置 →「从旧手机导入」扫码 → 直连旧手机 → AES-GCM 加密传输 → 合并导入。
- 交换格式：双端统一 JSON（打卡 + 手动记录 + 城市库版本），Android ↔ iOS 互通。
- 合并规则：打卡按（日期, 时段）、手动记录按日期去重，**新手机已有的记录一律保留**；
  导入后按本机城市库对导入坐标重解析（幂等）。
- 安全：密钥只经二维码（线下信道）传递、一次有效；指纹不符的连接直接断开；
  页面关闭即失效；传完自动停止。
- 失败引导：提示确认两台手机在同一 Wi-Fi（或旧手机开热点），可重新扫码。

### 6.2 界面外观（v0.7）

- **深色模式**：双端跟随系统自动切换（浅色/深色两套 token 色板），小组件同步适配；
  Android 关闭 OEM「强制深色」以免第三方反色破坏配色。
- 文案目前仅中文；多语言与平板适配列入后续版本。

### 6.3 桌面小组件（v0.8 重做）

- 尺寸双端统一 **2×2**（iOS systemSmall；Android targetCell 2×2、最小 110dp），中号不再提供。
- 信息层级「一城一数」：今年待得最久的城市名（17pt）+ 天数（44pt）是唯一锚点，
  第 2、3 名退为两行 13pt 脚注；不放应用名、不加高光/描边/阴影/水印，一层实心底面，
  圆角与内容边距交给系统（iOS containerBackground；Android 12+ 系统小组件圆角，旧系统 20dp）。
- 颜色只用系统 primary / secondary 两级 + 大数字一处品牌青（浅 #1F6289 / 深 #7CC0E8）；
  iOS 18 着色模式下大数字随用户主题色、其余变白。
- 边界处理：空态保留年份并提示；单城隐藏脚注；长城市名先缩到 0.8 再截断；最宽数值降一档字号；
  Android 按启动器给出的高度收脚注行；整块合并朗读。
- 备选底面（预览页可选）：系统材质（iOS 真模糊，Android 只能高不透明度近似）、品牌单色渐变。

## 7. 版本号策略（已确认）

- 起始 **0.1**；小功能改进 → 0.2、0.3…；bug 修复 → 0.1.1、0.1.2…；
  超大功能 / 架构或设计重构 → 1.0.0、2.0.0…
- 每个版本打 git tag（`v0.1`）并发布 GitHub Release（Android 附 APK）。
